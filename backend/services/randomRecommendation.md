# 随机美食

在桌面或手机的“更多”菜单中选择“随机美食”开启一轮推荐。首次抽取记录当前地图中心；“再换一家”保持该中心，“按当前地图中心重新抽取”更新中心并清空最近推荐记录。查看地点会打开现有地点弹窗。

`GET /places/random?lat=23&lng=113&excludeIds=1,2`

- 无需登录；登录后前端附带 Bearer token，后端复用 JWT/Redis 会话检查，只读取当前用户的画像。无效凭证返回鉴权错误，不使用请求参数指定的用户。半径固定为 5km 直线距离，与地图缩放、当前已加载标记无关。
- 先按球面包围矩形粗筛，再精确计算距离；包含 5km 边界，排除无效坐标和分类含“避雷”的地点。
- 完整候选池少于 5 家时返回 `place: null`，提示“附近好像没有结果，换个地方试试吧”。
- `excludeIds` 可选，最多两个地点 ID。先判断完整候选池数量，再排除最近推荐的两家。
- 原始权重：`W = 1 + 1/(1+d/2) + 0.3*C + 0.4*f/(f+5)`。`d` 单位为公里，`C` 复用 `placeDetailCompleteness`，`f` 为收藏用户去重数量。
- 游客、无有效画像或向量不可用时，抽取概率为剩余参与店铺的 `W / sum(W)`。
- 个性化在排除最近两家后计算：归一化用户向量与有效地点向量做余弦相似度 `s`，将其截断到 `[0,1]`；缺失、待更新或无效地点向量按 `s=0` 处理。偏好分布为 `Ppref = W*exp(4*s) / sum(W*exp(4*s))`。
- 混合强度 `a = 0.8 * min(1, vector_place_count/5) * vector_place_count/source_place_count`，最终概率 `P = (1-a)*W/sum(W) + a*Ppref`。最多 80% 倾向偏好，至少 20% 保留原始分布；样本少、画像覆盖不完整时降低个性化影响。所有符合条件的店都保留非零概率。候选没有正相似度时使用基础权重。
- 用户向量通过已有画像服务按需刷新，使用当前有效地点向量、本地计算，不增加 Embedding/DeepSeek 调用。画像或向量读取失败时退回基础权重，地点查询本身失败仍返回 500。
- 成功推荐响应包含 `place`、`distanceKm`、`candidateCount`、`personalized`；`personalized` 表示本次抽取概率是否使用偏好，并非对选中店铺的喜好保证。向量与用户行为明细不会放入推荐响应。候选不足时保持原有 `place: null` 响应。所有响应禁止缓存。
- 前端关闭面板或切换登录账号时取消在途请求，忽略过期响应；抽取期间禁用重复操作。换账号会开始新一轮抽取，避免沿用前一账号的结果。

验证：在 `backend` 目录运行 `npm run test:random`。使用临时数据库检查公式、概率分布、范围边界、收藏人数、防重复、候选门槛及 HTTP 接口，不修改应用数据库。
